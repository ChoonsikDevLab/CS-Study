# Chapter 4 | 자료구조

## 자료구조의 큰 그림
- **자료구조란?** 데이터를 어떻게 구조화하고 저장할 것인가를 규정하는 개념.
- **알고리즘과의 관계:** 어떤 자료구조를 쓰느냐에 따라 가능한 알고리즘이 달라지며, 알고리즘을 완전히 이해하려면 자료구조 지식이 필수적.
- **시간 복잡도 & 공간 복잡도:** 프로그램 성능을 평가하는 핵심 지표. 시간 복잡도는 연산 횟수 기반, 공간 복잡도는 메모리 사용량 기반이다.

---

## 배열과 연결 리스트
### 배열 (Array)
- **특징:** 동일 타입 데이터를 연속된 메모리 공간에 저장, 인덱스를 통한 접근 O(1).
- **장점:** 인덱스 기반 빠른 접근, 메모리 효율적, 구현 용이.
- **단점:** 삽입/삭제 시 O(n), 크기 고정으로 유연성 낮음.
- **용도 예시:** 문자열, 이미지, 게임 맵 등 연속적 데이터 저장

### 연결 리스트 (Linked List)
- **구조:** 노드가 데이터 + 다음 노드 포인터를 가지는 형태, 메모리 비연속적.
- **장점:** 삽입/삭제 시 O(1) (위치 알고 있을 경우), 동적 크기 조절 유리.
- **단점:** 인덱스 기반 접근 불가, 특정 요소 접근 시 O(n), 추가 포인터 메모리 필요.
- **용도 예시:** 음악 재생 목록, Undo/Redo 기능, 동적 데이터 관리

---

## 스택과 큐

### 스택 (Stack)
- **정의:** LIFO 방식 (마지막에 삽입된 요소가 먼저 제거).
- **연산:** `push`, `pop`.
- **장점:** 연산 단순, 상단만 조작하여 O(1) 속도.
- **단점:** 단일 방향 접근만 가능, 크기 제한 시 유연성 낮음.
- **용도 예시:** 함수 호출 스택, 뒤로 가기 기능 등.

### 큐 (Queue)
- **정의:** FIFO 방식 (먼저 들어간 요소가 먼저 나감).
- **연산:** `enqueue`, `dequeue`.
- **장점:** 순서를 유지하며 처리, 연산 단순, 양끝 접근 가능.
- **단점:** 중간 요소 접근 비효율적, 배열 기반 시 공간 재배치 필요 가능.
- **용도 예시:** 프린터 대기열, 스레드 관리 등.

---

## 해시 테이블 (Hash Table)
- **구조:** 키를 해시 함수로 변환해 배열에 저장.
- **충돌 처리:**  
  - 체이닝(Chaining): 동일 인덱스에 연결 리스트로 저장  
  - 오픈 어드레싱(Open Addressing): 다른 빈 슬롯을 찾아 저장
- **장점:** 평균적으로 삽입/검색/삭제 O(1), 빠른 데이터 접근.
- **단점:** 충돌 발생 시 최악 O(n), 순서 유지 불가.
- **용도 예시:** 캐시 구현, 데이터베이스 인덱스, 키-값 매핑

---

## 트리 (Tree)
- **정의:** 계층적 데이터 표현을 위한 비선형 자료구조, 노드와 간선으로 구성.
- **용어 정리:** 루트(Root), 부모/자식 관계, 형제(Sibling), 단말 노드(Leaf) 등.
- **용도 예시:** 파일 시스템 계층, 데이터베이스 인덱스 (예: B-Tree, AVL 등).

---

## 그래프 (Graph)
- **정의:** 노드(Vertex)와 간선(Edge)으로 구성된 비선형 자료구조.
- **종류:** 방향 그래프 (Directed), 무방향 그래프 (Undirected).
- **표현 방식:** 인접 행렬 (Adjacency Matrix), 인접 리스트 (Adjacency List).
- **용도 예시:** 네트워크, 길찾기, 관계 표현 등.

---

## 요약

| 자료구조         | 특징 요약                          | 장점                          | 단점                            |
|------------------|-----------------------------------|-------------------------------|----------------------------------|
| 배열             | 연속 메모리, 인덱스 O(1) 접근      | 접근 속도 빠름                | 삽입/삭제 비효율, 크기 고정     |
| 연결 리스트       | 노드 기반, 메모리 비연속적         | 삽입/삭제 O(1), 유연함         | 순차 접근, 추가 메모리 필요     |
| 스택             | LIFO 방식                         | 연산 단순, O(1) 속도          | 한쪽 접근만, 유연성 낮음        |
| 큐               | FIFO 방식                         | 순서 유지, O(1) 삽입/삭제     | 중간 접근 비효율, 공간 제한 가능 |
| 해시 테이블       | 키-값 매핑, 배열 + 해시 함수 사용  | 평균적으로 삽입/검색/삭제 O(1), 빠른 접근 | 충돌 처리 필요 (체이닝, 오픈 어드레싱: 선형/이차/Double Hashing) |
| 트리             | 계층 구조, 비선형 표현            | 구조적, 인덱스 구현 용이       | 복잡한 구조                      |
| 그래프           | 노드 간 관계 표현                  | 복잡한 관계 표현 유리          | 구현 및 알고리즘 복잡            |


## 예상 질문

<details>
<summary>배열과 연결 리스트의 차이점은 무엇인가요?</summary>
  
---
  
`배열`은 연속된 메모리 공간에 데이터를 저장해서 인덱스로 O(1)에 접근할 수 있는 장점이 있습니다. 

하지만 크기가 고정되어 있고, 삽입이나 삭제 시에는 데이터를 한 칸씩 이동해야 하므로 O(n)이 걸립니다.

<br>

반면에 `연결 리스트`는 노드 단위로 데이터를 저장하고 포인터로 연결하는 방식이라 삽입·삭제가 빠릅니다. 

하지만 임의 접근이 불가능하고 특정 인덱스로 접근하려면 순차 탐색이 필요해서 O(n)이 걸립니다.

---

</details>

<details>
<summary>PriorityQueue는 어떤 자료구조로 구현되어 있나요?</summary>
  
---
  
Java의 PriorityQueue는 내부적으로 힙(Heap) 자료구조, 구체적으로는 **이진 힙(Binary Heap)** 으로 구현되어 있습니다. 

삽입과 삭제 연산이 O(log n) 시간에 처리되고, 항상 가장 높은 우선순위를 가진 요소를 효율적으로 꺼낼 수 있습니다.

---

</details>

<details>
<summary>Java의 HashMap은 내부적으로 어떻게 동작하나요?</summary>
  
---
  
HashMap은 해시 함수를 사용해 key의 해시값을 구한 뒤, 배열의 인덱스로 변환하여 데이터를 저장합니다.

충돌이 발생하면 체이닝(LinkedList, JDK 8 이후에는 일정 기준 이상이면 Red-Black Tree로 변환) 방식으로 처리합니다.

평균적으로 검색, 삽입, 삭제 모두 O(1)에 가능하지만, 충돌이 많아지면 최악의 경우 O(n)까지 성능이 떨어질 수 있습니다.

---

</details>

<details>
<summary>스택(Stack)과 큐(Queue)의 차이를 설명하고, 각각 어떤 상황에서 유용할까요?</summary>
  
---
  
스택은 LIFO 구조로, 마지막에 들어온 데이터가 먼저 나갑니다. 그래서 함수 호출 스택, 실행 취소(Undo) 기능 같은 곳에서 사용됩니다.

큐는 FIFO 구조로, 먼저 들어온 데이터가 먼저 나갑니다. 그래서 작업 대기열, 요청 처리(예: 메시지 큐, 프린터 작업 큐) 같은 곳에서 자주 쓰입니다.

---

</details>

<details>
<summary>Set과 List의 차이점은 무엇인가요?</summary>
  
---
  
List는 순서를 보장하며 중복 데이터를 허용합니다. 그래서 인덱스를 통해 특정 위치의 데이터에 접근할 수 있습니다.

반면 Set은 중복을 허용하지 않고, 기본적으로 순서를 보장하지 않습니다. 다만 구현체에 따라 LinkedHashSet은 삽입 순서를, TreeSet은 정렬 순서를 유지할 수 있습니다.

---

</details>
