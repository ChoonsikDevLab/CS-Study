# 5. 네트워크
여러 대의 장치가 그물처럼 연결되어 정보를 주고받는 통신망의 구조와 프로토콜

## 1) 네트워크 기초

### 네트워크 구조
- **네트워크**: 노드(네트워크 기기)와 간선(유무선 통신 매체)으로 이루어진 **그래프** 형태
- **네트워크 토폴로지**: 노드 간 연결 구조 (망형, 트리형, 링형, 성형, 버스형)

### 네트워크 구성 요소
- **호스트**: 네트워크 가장자리에 위치하며 데이터를 송수신하는 최종 장치
- **클라이언트**: 요청을 보내는 호스트
- **서버**: 응답을 보내는 호스트
- **중간 노드**: 호스트 간 데이터 전송을 돕는 네트워크 장비 (스위치, 라우터)

### LAN과 WAN
- **LAN**(Local Area Network): 가정이나 기업처럼 비교적 가까운 거리를 연결하는 근거리 네트워크
- **WAN**(Wide Area Network): LAN과 LAN을 연결하는 원거리 네트워크, **ISP**가 주로 구축하고 관리

### 패킷 교환과 주소
- **패킷**: 데이터를 작은 단위로 쪼갠 것으로, **페이로드**(실제 데이터)와 **헤더**(부가 정보)로 구성
- **IP 주소**: 네트워크상에서 호스트를 식별하는 논리적 주소
- **MAC 주소**: 네트워크 인터페이스의 물리적 주소

### 전송 방식
- **유니캐스트**: 1:1 통신 방식
- **브로드캐스트**: 네트워크 내 모든 호스트에게 메시지 전송

### 프로토콜과 참조 모델
- **프로토콜**: 네트워크에서 노드 간 통신을 위한 합의된 규칙 (IP, TCP, UDP, HTTP 등)
- **OSI 7계층 모델**: 물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용 계층
- **TCP/IP 모델**: 네트워크 액세스, 인터넷, 전송, 응용 계층 (4계층)

### 캡슐화와 역캡슐화
- **캡슐화**: 송신 측에서 각 계층을 지나며 헤더를 추가하는 과정
- **역캡슐화**: 수신 측에서 각 계층을 지나며 헤더를 제거하는 과정

## 2) 물리/데이터링크 계층

### 이더넷
- 유선 LAN에서 사용하는 기술 표준 (IEEE 802.3)
- 통신 속도, 매체, 프레임 형식 등을 정의

### 이더넷 프레임
이더넷 네트워크에서 주고받는 데이터 단위
- 수신지/송신지 **MAC 주소**
- 타입, 데이터(페이로드), **FCS**(오류 검출) 필드로 구성

### 통신 매체
- **트위스티드 페어 케이블**: 구리선을 꼬아 만든 유선 케이블, 카테고리 등급으로 성능 구분
- **WiFi**: 전파를 이용하는 무선 LAN 기술 (IEEE 802.11), 2.4GHz/5GHz 주파수 대역 사용

### 네트워크 장비
- **NIC**: 컴퓨터를 네트워크에 연결하는 하드웨어, MAC 주소 부여
- **허브**: 물리 계층 장비, 들어온 신호를 모든 포트로 전달 (반이중 통신)
- **스위치**: 데이터링크 계층 장비, **MAC 주소 테이블**을 학습하여 목적지 포트로만 전달 (전이중 통신)

## 3) 네트워크 계층 (IP)

### IP의 특징
- 주된 목적: **주소 지정**과 **단편화**
- **신뢰할 수 없는** 프로토콜: 전송을 보장하지 않음
- **비연결형** 프로토콜: 사전 연결 과정 없음

### IP 주소 체계
- **IPv4**: 32비트 주소로 **네트워크 주소**와 **호스트 주소**로 구분
- **클래스풀 주소**: A, B, C 클래스로 구분 (주소 낭비 문제)
- **클래스리스 주소**(CIDR): **서브넷 마스크**로 네트워크와 호스트 부분을 유연하게 구분

### 공인 IP와 사설 IP
- **공인 IP**: 전 세계에서 유일한 주소
- **사설 IP**: 내부 네트워크에서만 사용되는 주소
- **NAT**: 사설 IP를 공인 IP로 변환하는 기술

### IP 주소 할당
- **정적 할당**: 수동으로 IP 주소 직접 설정
- **동적 할당**: **DHCP** 프로토콜을 통한 자동 할당

### 관련 프로토콜
- **ICMP**: IP의 비신뢰성을 보완하는 오류 보고 및 진단 프로토콜
- **ARP**: IP 주소를 통해 상대방의 MAC 주소를 알아내는 프로토콜

## 4) 전송 계층 (TCP/UDP)

### 포트
- 하나의 호스트에서 실행 중인 여러 프로세스를 구분하는 번호
- IP 주소와 포트 번호 조합으로 특정 프로세스 식별

### TCP (Transmission Control Protocol)
**신뢰성** 있는 **연결형** 프로토콜

#### TCP 주요 특징
- **3-way 핸드셰이크**: 데이터 전송 전 SYN과 ACK 패킷으로 연결 수립
- **4-way 핸드셰이크**: 데이터 전송 후 FIN과 ACK 패킷으로 연결 종료
- **오류/흐름/혼잡 제어**:
    - 재전송을 통한 오류 제어
    - 수신 측 처리 속도에 맞추는 흐름 제어
    - 네트워크 혼잡 상황에 따른 전송량 조절

### UDP (User Datagram Protocol)
- **비신뢰성**, **비연결형** 프로토콜
- 신뢰성 보장 기능이 없어 TCP보다 빠르지만 데이터 유실이나 순서 변경 가능

## 5) 응용 계층 (HTTP)

### DNS (Domain Name System)
- **도메인 네임**을 실제 IP 주소로 변환해주는 시스템
- `www.example.com`과 같은 이름을 192.168.1.1 같은 IP로 변환

### URI와 URL
- **URI**: 웹상의 자원을 식별하기 위한 통일된 방식
- **URL**: 자원의 '위치'를 기반으로 식별하는 방식 (URI의 한 종류)

### HTTP 기본 특징
- **요청-응답 기반**: 클라이언트가 **요청 메시지**를 보내면 서버가 **응답 메시지**를 보냄
- **스테이트리스**: 서버가 클라이언트의 이전 요청 상태를 기억하지 않음
- **지속 연결**: 하나의 TCP 연결로 여러 요청과 응답 처리 (HTTP/1.1 이상)

### HTTP 메시지 구조
- **시작 라인**: 요청 라인 또는 상태 라인
- **헤더**: 메타데이터 정보
- **메시지 본문**: 실제 전송할 데이터

### HTTP 확장 기능
- **쿠키**: 서버가 클라이언트에 저장하는 작은 데이터, 상태 유지에 사용
- **캐시**: 자주 요청하는 자원을 저장하여 응답 속도 향상 및 네트워크 부하 감소
- **콘텐츠 협상**: 클라이언트 선호에 따라 적절한 버전의 자원 제공

### HTTPS 보안
- **HTTPS**: HTTP에 **SSL/TLS** 보안 계층을 추가하여 통신 내용 암호화
- **SSL/TLS 핸드셰이크**: 암호화 통신 시작 전 암호화 방식과 키 교환 과정

### 프록시와 로드 밸런싱
- **프록시 서버**: 클라이언트와 서버 사이에서 요청과 응답을 중개하는 서버
- **로드 밸런싱**: 여러 서버에 트래픽을 분산시켜 과부하 방지
- **가용성**: 시스템이 정상적으로 운영되는 시간 비율

### 스케일링
- **스케일 업**: 서버 성능 향상 (수직 확장)
- **스케일 아웃**: 서버 대수 증가 (수평 확장)

# 예상 질문

<details>
<summary><b>TCP와 UDP의 차이점을 설명해주세요.</b></summary>
<br>
TCP는 신뢰성이 있는 연결형 프로토콜입니다. 3-way 핸드셰이크로 연결을 수립하고, 오류 제어, 흐름 제어, 혼잡 제어 기능을 제공하여 데이터의 정확한 전송을 보장합니다. 하지만 이러한 기능들로 인해 UDP보다 속도가 느립니다.<br><br>
UDP는 비신뢰성, 비연결형 프로토콜입니다. 연결 수립 과정이 없고 오류 제어 기능도 제공하지 않아 TCP보다 빠르지만, 데이터 유실이나 순서 변경이 발생할 수 있습니다. 실시간 통신이나 스트리밍에 주로 사용됩니다.
</details>

<details>
<summary><b>3-way 핸드셰이크와 4-way 핸드셰이크에 대해 설명해주세요.</b></summary>
<br>
<b>3-way 핸드셰이크</b>는 TCP 연결을 수립하는 과정입니다.<br>
1. 클라이언트가 서버에 SYN 패킷을 보냄<br>
2. 서버가 SYN+ACK 패킷으로 응답<br>
3. 클라이언트가 ACK 패킷을 보내며 연결 수립 완료<br><br>
<b>4-way 핸드셰이크</b>는 TCP 연결을 종료하는 과정입니다.<br>
1. 클라이언트가 FIN 패킷을 보냄<br>
2. 서버가 ACK 패킷으로 응답<br>
3. 서버가 FIN 패킷을 보냄<br>
4. 클라이언트가 ACK 패킷을 보내며 연결 종료 완료
</details>

<details>
<summary><b>HTTP와 HTTPS의 차이점을 설명해주세요.</b></summary>
<br>
HTTP는 평문으로 데이터를 전송하는 프로토콜로, 전송 과정에서 제3자가 데이터를 엿볼 수 있어 보안에 취약합니다.<br><br>
HTTPS는 HTTP에 SSL/TLS 보안 계층을 추가한 프로토콜입니다. SSL/TLS 핸드셰이크를 통해 암호화 키를 교환하고, 모든 통신 내용을 암호화하여 전송합니다. 이를 통해 데이터의 기밀성, 무결성, 인증을 보장할 수 있습니다.
</details>

<details>
<summary><b>쿠키와 세션의 차이점을 설명해주세요.</b></summary>
<br>
<b>쿠키</b>는 서버가 클라이언트(브라우저)에 저장하는 작은 데이터 조각입니다. 클라이언트 측에 저장되며, 매 요청 시 서버로 전송됩니다. 보안에 취약하고 용량 제한이 있지만 서버 부하가 적습니다.<br><br>
<b>세션</b>은 서버 측에 사용자 정보를 저장하고, 클라이언트에는 세션 ID만 쿠키로 저장하는 방식입니다. 서버에 저장되어 보안이 좋지만, 서버 메모리를 사용하여 부하가 증가할 수 있습니다.
</details>
