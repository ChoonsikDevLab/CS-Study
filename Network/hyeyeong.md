# Chapter 5 | 네트워크 핵심 요약

---

## 네트워크의 큰 그림
- **네트워크**: 노드(node)와 간선(edge)으로 구성된 그래프 구조
- **토폴로지**: 버스형, 스타형 등
- **호스트**
  - 클라이언트(client): 요청 송신
  - 서버(server): 요청 응답
- **LAN vs WAN**
  - LAN: 제한된 공간 내 네트워크
  - WAN: 지리적 분산, ISP 관리
- **패킷 교환 네트워크**
  - 데이터는 패킷 단위로 전송, 수신 시 재조립
  - 패킷 구성: 헤더(header), 페이로드(payload), 트레일러(trailer)

---

## 물리 계층과 데이터 링크 계층
- **이더넷(Ethernet)**: LAN에서 널리 사용, IEEE 802.3 표준
- **프레임 구성**
  - 프리앰블(Preamble)
  - MAC 주소 (송신/수신)
  - 타입/길이 필드
  - 데이터(payload)
  - FCS (Frame Check Sequence)
- **전송 매체**
  - 유선: Twisted Pair Cable (STP, FTP, UTP)
  - 무선: 전파, WiFi (2.4/5GHz), 채널 단위
- **NIC**: MAC 주소 부여, 신호 ↔ 프레임 변환
- **허브 vs 스위치**
  - 허브: 단순 리피터, 반이중, 충돌 도메인 공유
  - 스위치: MAC 학습, 전이중, 충돌 도메인 분리, VLAN 지원

---

## 네트워크 계층 - IP
- **IP 프로토콜**
  - IPv4: 32비트 주소
  - IPv6: 128비트 주소
- **서브넷팅**: 주소 효율적 분할
- **라우팅**
  - 정적 라우팅: 수동 경로
  - 동적 라우팅: 라우팅 프로토콜 사용

---

## 전송 계층 - TCP와 UDP
- **TCP**
  - 연결 지향, 순서 보장, 오류 검출, 흐름 제어
  - 3-way 핸드셰이크: 연결 설정
  - 4-way 핸드셰이크: 연결 종료
- **UDP**
  - 비연결 지향, 빠른 전송, 신뢰성 미보장
  - 실시간 스트리밍, VoIP 적합

---

## 응용 계층 - HTTP의 기초
- HTTP: 클라이언트와 서버 간 데이터 전송
  - 요청(Request): GET, POST, PUT, DELETE
  - 응답(Response): 상태 코드(200, 404 등)
- Stateless: 각 요청 독립적
- HTTPS: SSL/TLS 적용, 보안 강화

---

## 응용 계층 - HTTP의 응용
- 쿠키(Cookie): 클라이언트 측 상태 저장
- 세션(Session): 서버 측 상태 관리
  - 세션 ID: 사용자 상태 식별
- JWT: JSON 형식 토큰, 사용자 인증/정보 교환

---

## 프록시와 안정적인 트래픽
- **프록시 서버**: 클라이언트 요청 대리 전송, 보안/캐싱/접근 제어
- **리버스 프록시 서버**: 클라이언트 요청을 내부 서버로 분배
  - 로드 밸런싱, SSL 종료, 보안 강화

---

<summary>로드 밸런서의 역할과 동작 방식에 대해 설명해주세요.</summary>
  
---
  
로드 밸런서는 여러 서버에 트래픽을 분산시켜 서버 부하를 줄이고 가용성과 확장성을 확보하는 역할을 합니다.

동작 방식은 크게 L4(전송 계층, IP/Port 기반 분산) 과 L7(애플리케이션 계층, URL/헤더 기반 분산) 으로 나눌 수 있으며, 헬스 체크를 통해 정상 서버로만 요청을 보내도록 동작합니다.

---

</details>

<details>
<summary>HTTPS에서 TLS/SSL이 동작 방식을 간단히 설명해주세요.</summary>
  
---
  
HTTPS는 TLS/SSL 프로토콜을 사용해 데이터 암호화, 무결성 보장, 서버 인증을 수행합니다.

핵심 동작은 핸드셰이크 과정에서 대칭키를 안전하게 교환하고, 이후 해당 키를 사용해 빠른 대칭키 암호화 방식으로 통신합니다.

---

</details>

<details>
<summary>프록시와 리버스 프록시의 차이점을 설명해주세요.</summary>
  
---
  
- 프록시 서버: 클라이언트가 인터넷에 직접 연결되지 않고, 중간에 위치한 서버가 대신 요청을 전달합니다. 주로 보안, 캐싱, 접근 제어 목적에 사용됩니다.

- 리버스 프록시 서버: 클라이언트 요청을 받아 내부 서버로 분배하는 역할을 하며, 주로 로드 밸런싱, SSL 종료, 보안 강화에 활용됩니다.

---

</details>

<details>
<summary>Stateful과 Stateless 서버의 차이와, 각각 어떤 상황에서 적합한지 설명해주세요.</summary>
  
---
  
- Stateful 서버: 클라이언트의 상태(Session, 로그인 정보 등)를 서버가 유지합니다.
- 예: 채팅 서버, 온라인 게임 서버  

- Stateless 서버: 서버가 상태를 저장하지 않고, 모든 요청을 독립적으로 처리합니다.
- 예: REST API 서버, 웹 서버

---

</details>
